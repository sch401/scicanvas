**必须守住的约定**

1. **核心库不依赖界面。** 一切计算、数据处理、版面都放在 `scicanvas-core`，不引用 egui。这样将来 Python 包、命令行、网页版都能直接复用。
2. **所有用户操作都是命令。** 新功能先在 `commands.rs` 注册命令（id、名称、图标、可用条件），功能区按钮、右键菜单、快捷键、命令面板、将来的脚本录制都调用同一个命令。
3. **屏幕和导出共用 `scene`。** 新的图元素（误差棒、文字标注、多图层）只加在 `scene.rs`，界面绘制和 SVG / PNG / PDF 导出自动一致。
4. **数值结果必须有对照。** 每个分析功能都要有测试，用公认的参考值（NIST 认证数据、SciPy、R）比对，不能只“看起来对”。
5. **项目文件向后兼容。** 新字段一律加 `#[serde(default)]`，旧项目必须能打开。

## M1 撤销与重做（约 1 周）

**当前状态：基础功能已实现并有自动化回归。** 编辑事务、命令标记、连续输入/拖动合并、快捷键及窗口恢复已接入。单次事务仍复制完整项目，列数据共享与大数据性能优化后续评估。以下保留现有实现约定及验收标准。

采用整个项目快照：一次编辑事务保留一份修改前快照，连续输入和拖动复用。实际写入设置修改标记，提交时核对最终变化；空闲帧跳过整项目比较。单次事务开始仍复制项目，列数据共享结构待大数据性能测试后评估。

**设计**

- 核心库已有 `history.rs`：`History { undo, redo, pending }`；快照保存项目、操作名称和内存估算。
- 接口：`begin(current, label)` 开启事务，`changed()` 标记实际写入，`commit(current)` 提交最终变化并更新重做栈；`undo(current) -> Option<Project>`；`redo(current) -> Option<Project>`；`undo_label()` / `redo_label()` 给提示文字用。
- 上限：最多 100 步，或估算内存超过 300 MiB 时丢掉最旧的。
- 只记录项目数据（工作簿、图形、列属性）。窗口位置、选区、缩放视图不进历史。

**接入点**

1. 命令结构加一个字段 `modifies: bool`。修改类命令在定义旁调用 `.modifies()`；`run_command` 执行前开启事务、执行后设置修改标记并提交；如果命令执行后项目没变（比如条件不满足），把这次快照丢掉。
2. 工作表里不走命令的修改也要记：单元格编辑提交、Delete 清除、粘贴、长名称 / 单位 / 注释的修改。
3. 连续输入合并：同一个文字框的首次实际修改捕获快照，后续输入复用；结束编辑时提交。绘图属性窗口的一次拖动使用同一事务。
4. 新增命令 `edit.undo`（Ctrl+Z）、`edit.redo`（Ctrl+Y / Ctrl+Shift+Z），放进快速访问栏。提示文字写“撤销：删除列 B”。
5. 当前正在编辑的单元格另算：编辑框里的 Ctrl+Z 先交给文字框。
6. 撤销后，已删除的窗口要能重新显示；不存在的对象对应的窗口状态、选区要清掉。

**验收**

- 核心库测试：连续 5 步修改后全部撤销，项目与初始完全相等；撤销后又做新修改，重做栈清空；超过上限时丢掉最旧的。
- 界面手动检查：删除列、粘贴、拟合（会加列和曲线）、排序、新建图形、删除工作簿，都能撤销和重做。

## M2 非线性拟合（约 4 周）

**当前状态：待实现。** 已有线性和多项式拟合；本节的 LM、表达式引擎、非线性函数库及 NIST 验证属于后续任务。

这是 Origin 最核心的功能，也是用户信不信任这个软件的关键。目标是：NIST 全部 27 个非线性认证数据集上，参数与认证值至少 6 位有效数字一致。

**模块划分（全部在核心库）**

| 文件 | 职责 |
| --- | --- |
| `expr/` | 表达式引擎：词法、Pratt 语法分析、语法树求值、符号求导。M4 的列公式也用它 |
| `fit/lm.rs` | Levenberg-Marquardt 求解器，只认“残差函数 + 雅可比”，不管公式从哪里来 |
| `fit/model.rs` | 拟合模型：参数名、初值、是否固定、上下限；内置函数或用户公式 |
| `fit/library.rs` | 内置函数库，每个函数带解析导数和自动初值估计 |
| `fit/report.rs` | 统计量、置信区间、残差 |
| `stats/dist.rs` | t、F、卡方分布的分位数（用不完全 Beta / Gamma 函数），M6 也用 |
| `tests/nist/` | 27 个 NIST 数据文件与认证值 |

**算法要点**

每次迭代求解下面的方程，得到参数增量 δ（J 是雅可比，W 是权重对角阵，r 是残差，λ 是阻尼系数）：

```latex
\left(J^{\mathsf T} W J + \lambda\,\operatorname{diag}(J^{\mathsf T} W J)\right)\delta = J^{\mathsf T} W r
```

- 用 QR 分解或 SVD 求解，不要直接求逆，否则 MGH10、Bennett5 这类病态问题会失败。推荐用 `nalgebra` 做矩阵运算。
- λ 策略：初值 1e-3；误差平方和下降则 λ 除以 10 并接受，否则乘以 10 重试。
- 雅可比：内置函数和用户公式都用符号求导；求导失败时退回中心差分，步长 h = √ε · max(|p|, 1)。
- 收敛条件（任一满足即停）：误差平方和相对变化 < 1e-10；参数相对变化 < 1e-10；梯度范数 < 1e-12；迭代 > 400 次则报告“未收敛”。
- 固定参数：从雅可比里去掉对应列。上下限：用变量变换（双边用 sin，单边用平方根）把有界问题转成无界问题。
- 权重：无权重、按误差列（w = 1/σ²）、按 1/y 三种。
- 参数协方差 = s² · (JᵀWJ)⁻¹，其中 s² = 误差平方和 / (n − p)；用误差列做权重时可选“不用 s² 缩放”。

**报告内容**：参数值、标准误、t 值、p 值、95% 置信区间、依赖度（判断参数是否冗余）、误差平方和、约化卡方、R²、调整后 R²、AIC、BIC、迭代次数与收敛原因。结果写入新工作表（参数表 + 拟合曲线 + 残差），曲线加到图上。

**内置函数库（第一批 20 个）**

| 类别 | 函数 | 自动初值的思路 |
| --- | --- | --- |
| 指数 | ExpDec1、ExpDec2、ExpGrow1、ExpAssoc | 取 ln(y − y0) 做线性拟合得到 t1 |
| 峰函数 | Gauss、Lorentz、Voigt、PseudoVoigt | 最大值位置为中心，半高宽为宽度 |
| S 型 | Boltzmann、Logistic、Hill、DoseResp | 两端平台为 A1 / A2，过半位置为 x0 |
| 幂 / 对数 | Allometric1、Power、Log | 双对数坐标下线性拟合 |
| 周期 | Sine、SineDamp | FFT 主频率给周期 |
| 动力学 | MichaelisMenten、Arrhenius | 线性化变换（Lineweaver-Burk、ln k 对 1/T） |

用户公式写法：`y = A*exp(-x/t1) + y0`，自动识别未定义的名字为参数。

**NIST StRD 验证**

- 27 个数据集按难度：低（Misra1a、Chwirut1/2、Lanczos3、Gauss1/2、DanWood、Misra1b）、中（Kirby2、Hahn1、Nelson、MGH17、Lanczos1/2、Gauss3、Misra1c/1d、Roszman1、ENSO）、高（MGH09、Thurber、BoxBOD、Rat42、MGH10、Eckerle4、Rat43、Bennett5）。
- 每个数据集从两组官方起始值各跑一次，比较参数、标准误、误差平方和的有效数字位数（LRE）。
- 验收：低、中难度全部 ≥ 6 位；高难度从第二组起始值 ≥ 6 位，第一组允许报告“未收敛”但不能给出错误结果。结果生成一张表放进文档，这是对外宣传“结果可信”的依据。
- 另外用 SciPy `curve_fit` 对内置函数各做 3 组仿真数据对照。

**界面**：拟合对话框左边选函数（带公式和示意图），中间参数表（初值、固定、上下限），右边实时预览初值曲线；按钮“初值估计”“迭代一次”“拟合到收敛”。报告窗口含残差图。拟合在后台线程跑，可取消。

## M3 作图底座与图型复刻（底座 4 周 + 六批共约 24 周，分散在整个路线里）

目标是复刻 Origin 功能清单里的全部 235 种图型。做法不是逐个写，而是先做一套“组合式”底座，再分六批补基础部件；每补一个部件，就一次解锁一批图型。

**为什么要组合式**

235 种图其实由二三十种部件拼成：图元（柱、线、点、面积、箱体、小提琴）、统计变换（分箱、核密度、均值 ± 误差、分位数）、坐标系（直角、极坐标、三元、史密斯圆、3D）、版面（多图层、多轴、多面板、边际图）。例如分组半小提琴图 = 按组分类 + 核密度 + 半边小提琴；风玫瑰图 = 分箱 + 堆叠柱 + 极坐标。部件写一次，图型只是配置。

### 底座（约 4 周，所有图型的前提）

**当前状态：基础结构已接入，组合能力继续扩展。**

| 部件 | 已实现 | 后续扩展 |
| --- | --- | --- |
| 作图描述 | X/Y、独立 X、14 图型、均值变换、配色、上下端映射 | 按列映射颜色/大小、分组、分面 |
| 页面 → 图层 → 曲线 | 多图层、网格/自由位置、透明叠放、独立视图、旧文件迁移 | 双 Y 轴、轴联动、多面板与插图专用工作流 |
| 坐标接口 | `Coord` 与线性/对数直角坐标；条形方向转换 | 极坐标、三元、史密斯圆、3D |
| 统计变换 | 原始数据与按相同 X 求均值 | 分组、SEM/置信区间、宽长表识别 |
| 配色 | Origin、Viridis 五节点插值、色盲友好配色 | 连续数据颜色映射、色阶条 |

以下为底座的完整目标范围：

1. **作图描述**（核心库 `plotspec.rs`）：用数据描述一张图——哪列映射到 X、Y、颜色、大小、分组、分面；统计变换；图元；坐标系；样式。拖放作图面板、图库推荐、模板、Python、操作录制、AI 一句话作图都产出它。
2. **页面 → 图层 → 曲线三层结构**：已取代原有单层 `Graph`；双 Y 轴、多面板、插图在此结构上扩展。旧项目文件通过迁移函数自动转换。
3. **坐标系抽象**：“数据坐标 → 屏幕坐标”做成可替换的接口（`trait Coord`），图元不关心自己画在哪种坐标里。
4. **统计变换管线**：原始数据 → 分组 → 变换（如均值 ± SEM）→ 图元，用户直接拿重复测量的原始数据作图，宽表、长表自动识别。
5. **颜色映射与色阶条**：内置 viridis、色盲友好等配色，热图、颜色映射散点、曲面共用。
6. **图型预设做成数据文件**：每种 Origin 图型一个预设（用哪些部件、默认样式、需要的数据形状、不满足时的提示）。每个预设配一份示例数据，自动生成图库缩略图，同时当作版面回归测试。预设最适合批量交给 GPT 写。
7. **拖放作图面板与图库**：左边列名，右边 X / Y / 颜色 / 分面几个格子，实时预览；图库缩略图用用户自己的数据画，不适合的图型变灰并说明原因。

在线模式下脚本经控制服务调用命令，和点按钮走同一条路；离线模式下同一个包直接调用编译成 Python 扩展的核心库。

- 软件启动时在 127.0.0.1 的随机端口开一个服务，生成一次性令牌，通过环境变量 `SCICANVAS_ADDR`、`SCICANVAS_TOKEN` 传给子进程。不带令牌的连接一律拒绝。

**3. `scicanvas` Python 包（第 2–3 周）**

```python
import scicanvas as sc
book = sc.active_book()
df = book.to_pandas()            # 列长名称做表头
book["D"] = df["B"].rolling(5).mean()
g = sc.plot(book, x="A", y=["B", "D"], kind="line")

print(res.params, res.r2)

```

## 用 GPT / Codex 协作写代码

最有效的分工是：你定任务和验收标准，AI 写代码和测试，CI 和参考数据判断对错。任务越小、接口越明确，结果越可靠。

**拆任务的规则**

1. 一个任务 = 一个模块或一个功能点，改动不超过 3 个文件、约 500 行。
2. 先做核心库、再做界面。核心库任务可以完全靠测试验收，AI 最擅长；界面任务要你自己点一遍。
3. 每个任务必须给出：要读的现有文件、函数签名、验收测试（最好你先写好或让 AI 先写测试你来审）。
4. 一个任务一个分支、一个 PR，过 CI 才合并。
5. 数值算法的任务，参考数据由你从官方来源下载（NIST、SciPy 输出），不要让 AI 自己“编”参考值。
