# Windows 性能基线

## 完整界面首帧与峰值内存（2026-10-19）

`cargo test --release -p scicanvas --bin scicanvas million_row_first_frame -- --ignored --nocapture`，同机 release。
测量程序生成 1,000,000 × 10 的 CSV 文本，经 `csv::book_from_text` 导入，选中一列画散点，打开工作簿与图形窗口，
在 1600×900 的无头 egui 上下文中跑完整界面帧（布局与三角化，不含 GPU 提交）。进程峰值工作集由外部每 20 ms 采样。

| 项目 | 结果 |
| --- | ---: |
| 导入（解析 + 建表） | 812 ms |
| 首帧 | 246 ms |
| 次帧（场景缓存命中） | 12.6 ms |
| 进程峰值内存 | 494 MB |

- 导入改为由文本逐行写入类型化列，不再生成整张字符串行表。
- 折线超过 4 倍绘图宽度的点数时按像素列保留首、末、最小、最大点；散点按半像素网格去重。
- 图形场景按图形设置、视图和所引用列的内容指纹缓存，数据与设置不变时直接复用，次帧不再重新排版。
- 峰值内存中字体约 56 MB、十列 f64 数据约 80 MB，其余为首帧排版的临时数据。原定 < 150 MB 的目标低于字体与数据本身之和，不作为验收线。

## 类型化列后的对照（2026-10-18）

同一基准程序、Windows 本机、Rust 1.99.0 release。CSV 数据形状及计时边界保持下文原记录的规则。

| 行数 × 列数 | CSV 字节 | 导入 ms | 单曲线散点排版 ms | 整表按 X 排序 ms |
| --- | ---: | ---: | ---: | ---: |
| 100,000 × 10 | 3,166,589 | 157.139 | 25.327 | 5.790 |
| 1,000,000 × 10 | 32,665,840 | 1461.616 | 184.746 | 54.457 |

百万行导入这次为 1.462 秒，较原记录 2.367 秒降低约 38%。排序从 685 ms 降至 54 ms，来自类型化比较与按索引复制数值/位图。CSV 构建消费单元格而非克隆整张行表，绘图直接读 ColumnView，数值分析不再反复解析数值列。

新增测试验证百万个规范数值的单列数据容量估算 < 12 MiB。该测试不是进程峰值内存测量。稀疏原文覆盖、CSV 原始字符串和临时表、绘图图元与撤销快照均会增加实际内存。完整首帧/GPU 和峰值内存 < 150 MB 目标继续验收。

下方为重构前历史基线，保留用于同机后续对照。

2026-10-16，当前 `Vec<String>` 数据模型，Windows 本机、Rust 1.99.0 优化构建。
执行 `cargo bench -p scicanvas-core --bench data_pipeline --locked`，无需新增依赖。

| 行数 × 列数 | CSV 字节 | 导入 ms | 单曲线散点排版 ms | 整表按 X 排序 ms |
| --- | ---: | ---: | ---: | ---: |
| 100,000 × 10 | 3,166,589 | 247.703 | 18.165 | 67.595 |
| 1,000,000 × 10 | 32,665,840 | 2367.378 | 175.138 | 685.067 |

每个规模运行一次，记录原始计时，适合作为本机结构改造前的初始基线。性能判断需在同机、相同构建模式下复测。
输入为倒序 X、9 列确定性整数 Y；CSV 生成不计入导入，导入包含解析与工作簿构建。
绘图计时为选中单列后的 `scene::layout_page`，包含数据解析、投影和图元生成；
窗口启动、GPU 提交、实际屏幕呈现和 SVG 文本序列化需单独测量。排序包含十列整表重排。
基准会校验导入行列数、排序首末值，防止操作失败产生虚假的快速结果。

第三阶段目标中的百万行十列导入 < 2 秒，当前这次测量为 2.367 秒。
首帧散点 < 500 ms、内存 < 150 MB 两项仍需完整界面与峰值内存测量，排版时间单独记录。
当前计时确认了类型化列与解析改造的优先级。此基准手动执行，避免将运行器负载波动变成 CI 功能失败。

## 设置窗口拖动（2026-10-25）

图形绘制指令按场景、显示尺寸和 DPI 缓存。移动设置窗口或图形窗口时复用矢量图元与文字排版，修改数据、设置、视图、尺寸或 DPI 时更新。颜色、大小和符号映射列也参与数据指纹，编辑这些列会刷新图形。SVG/PNG/PDF 导出继续使用原有场景和导出流程。

Windows 使用 eframe 自带的 wgpu 呈现路径，FIFO 队列和一帧延迟配置。保留原有字体和矢量文字绘制。

同机 AMD Radeon 780M，release 示例项目、非线性拟合窗口打开，连续请求更新约 3 秒的短压力对照：

| 指标 | 原 OpenGL | wgpu FIFO |
| --- | ---: | ---: |
| 进程 CPU 时间（包含启动） | 6359.4 ms | 2671.9 ms |
| 进程总运行时间 | 4557.8 ms | 4573.2 ms |
| 应用更新调用速率 | 518.8 /s | 234.9 /s |

此对照在绘制指令缓存加入前完成，进程 CPU 时间减少约 58%。调用速率包括应用更新，属于连续更新压力测试，不代表屏幕实际呈现帧率或用户拖动时的 CPU 百分比。绘制缓存的回归测试比较直接绘制与缓存绘制的网格、字体纹理、颜色、裁剪和位置，并验证平移复用、尺寸/DPI/内容变化更新。

## T9/T10 共享撤销与重算输入缓存（2026-10-31）

Windows 本机优化构建，执行 `cargo bench --locked -p scicanvas-core --bench data_pipeline -- --history-only`。数据为 1,000,000 行 × 10 数值列，连续修改第一列三个单元格，每次提交历史。深复制对照显式复制十列并比较项目，共享路径走实际 History::begin/changed/commit。原始一次测量如下。

| 项目 | 耗时 ms |
| --- | ---: |
| 显式整表深复制对照，3 次编辑 | 34.389 |
| 共享列撤销路径，3 次编辑 | 2.599 |
| 共享 Book 快照与相等比较，100 次 | 0.076 |

此处对照是同一构建内的显式深复制路径，记录这次运行结果。共享路径只复制发生修改的列，历史预算对同一列分配只计一次。应用的已重算 Book 快照使用同一共享存储，图形属性及图例位置变化时跳过拟合输入扫描。图形实际帧时间、GPU 呈现和其他数据分布继续使用各自性能场景。

## R2/R7 后台备份与连续事务（2026-10-31）

同机 Windows 优化构建、百万行 × 十数值列，每种场景独立进程各执行一次。命令为 `cargo bench --locked -p scicanvas-core --bench data_pipeline --all-features -- --continuous-review` 和 `--recovery-review`。

| 场景 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 同一事务连续写最后一行 60 次，并更新重算判断缓存 | 83.475 ms | 1.580 ms |
| 写入期间目标列发生的分配变化 | 60 次 | 1 次 |
| 恢复文件序列化、原子写入与同步 | 380.563 ms | 184.498 ms |
| 备份进程初始工作集 | 85,811,200 B | 85,835,776 B |
| 备份进程峰值工作集 | 373,768,192 B | 208,515,072 B |

连续事务对照分别使用持有 Book 副本的缓存与轻量数据版本签名，包含历史提交。备份约 107 MB，数据按原来的 Base64 数值编码保存。修改后先构造一次项目 Value，再通过 64 KiB 标准缓冲写入临时文件、同步和原子替换，元数据单独保存；没有缩进字符串的再解析和完整输出 Vec。实际应用在后台执行该路径，界面只捕获共享项目副本及草稿。

峰值指标来自 Win32 GetProcessMemoryInfo 的 PeakWorkingSetSize，是整个基准进程的峰值工作集。此处记录单次同机构建对照，恢复后的拟合、实际 GUI 帧时间和文件系统缓存变化分别看待。

## K0 启动后端探测（2026-10-31）

本机 Windows，AMD Radeon 780M Graphics，驱动 32.0.32015.7029，release 示例项目一次测量：DX12 适配器探测 221.235 ms；SCICANVAS_SMOKE_TEST=1 从启动进程至首帧后正常退出共 1726.079 ms。前者包含创建/枚举图形实例，不包含完整应用启动；后者包含启动、首帧和退出，不能作为单独首帧时间。DX12 有适配器时不初始化 Vulkan；否则再探测 Vulkan。实际后端和适配器写入日志。

本机还临时使用空后端验证原生错误框和启动失败日志，随后恢复正常后端选择。CI 新增 release 构建与首帧冒烟步骤，冒烟独立超时 60 秒。项目格式与图形场景/导出路径保持不变。
