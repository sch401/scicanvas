## 目标与原则

目标：让后续加功能时**改动集中在一处、出错能被测试抓住、新人（或 AI）能快速找到代码**。

每一步都必须遵守：

1. **只重构，不改行为。** 不顺带加功能、不改界面文字和布局、不改项目文件格式。
2. **每步一个提交**，提交前 `python tools/check.py` 全部通过。
3. **19 份 golden SVG、PDF/PNG 导出测试、项目文件往返测试结果不变。** 如果某步必须更新 golden，说明原因并单独提交。
4. 先加访问函数、再迁移调用点、最后删旧代码；不要一次性大替换。
5. 注释统一用中文；提交信息用英文。

### 结构性问题

1. **曲线数据用字符串键加多张平行映射表保存。** `Layer` 里的 `y_keys`、`x_by_y`、`base_by_y`、`row_by_y`、`line_only`、`curves` 都用 `"B"` 或 `"B@2"` 字符串关联同一条曲线。
   - 页面和映射模块之外有 62 处直接读写这些字段。
   - 删除一条曲线要同时清理 6 张表。最近修过的“删列后样式残留”“清空图层后标签列残留”都是漏清其中一张造成的。

2. **撤销事务靠手写三连。** `begin_edit` → 改 → `history.changed()` → `finish_edit` 共 54 处，漏写一步就会出现“改了但不能撤销”或“多出一步撤销”。
3. **分析操作重复。** 拟合、插值、非线性拟合、平滑、基线都重复同一套流程：
   1. 插入结果列（X、Y 各一次）；
   2. 找目标图形；
   3. 把结果挂到图层。
4. **界面测试辅助代码复制了 19 份**（`frame` 闭包或函数），另有点击宏、按文字找控件坐标的闭包各一份。
5. **两套 SVG 渲染栈并存。**
   - PNG 用 `resvg 0.37`（`usvg 0.37` / `rustybuzz 0.12`），PDF 用 `svg2pdf 0.13`（`usvg 0.45` / `rustybuzz 0.20`），exe 变大。
   - `deny.toml` 还有两条因此保留的“无人维护”豁免。
6. **现有脚本的入口说明不完整。** 仓库已有 `tools/check.py`、`tools/package_release.py`、`tools/third_party.py` 和 `docs/parity/build_parity.py`；1.7 重点补齐文档同步入口和 `CONTRIBUTING.md`，复用已有脚本。
