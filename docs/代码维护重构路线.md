- **B 列粘贴补充修复（2026-10-24）**：已有数值列粘贴文字时复用自适应写入，原数值按可往返表示保留；数值编辑格中的单值粘贴即时写入，Excel 行尾换行也正确交给表格。具有表格焦点时，普通非模态窗口不再全局阻止粘贴；日期校验保留，新粘贴成功后清除旧的转换提示，避免稍后覆盖新值。统一入口适用于所有现有和新增列；覆盖 A/B/C/D/Z/AA/AZ/CV 八个位置 × 普通/编辑状态 × 四种内容的 64 个场景，另覆盖从 D/Z/AA/CV 开始的 40 列整块粘贴和自动补列，以及设置窗口和日期拒绝回归，保留列角色、误差关联、其他单元格和撤销重做。
- 统计校正：当前 SVG 基线是 19 份；检查、发布和清单生成脚本已在仓库，1.7 按现有入口补充维护说明。

## 目标与原则

目标：让后续加功能时**改动集中在一处、出错能被测试抓住、新人（或 AI）能快速找到代码**。

每一步都必须遵守：

1. **只重构，不改行为。** 不顺带加功能、不改界面文字和布局、不改项目文件格式。
2. **每步一个提交**，提交前 `python tools/check.py` 全部通过。
3. **19 份 golden SVG、PDF/PNG 导出测试、项目文件往返测试结果不变。** 如果某步必须更新 golden，说明原因并单独提交。
4. 先加访问函数、再迁移调用点、最后删旧代码；不要一次性大替换。
5. 注释统一用中文；提交信息用英文。

### 结构性问题

1. **曲线数据用字符串键加多张平行映射表保存。** `Layer` 里的 `y_keys`、`x_by_y`、`base_by_y`、`row_by_y`、`line_only`、`curves` 都用 `"B"` 或 `"B@2"` 字符串关联同一条曲线。
   - 页面和映射模块之外有 62 处直接读写这些字段。
   - 删除一条曲线要同时清理 6 张表。最近修过的“删列后样式残留”“清空图层后标签列残留”都是漏清其中一张造成的。
   - 文件格式（v11 起的 `plots`）其实已经是“每条曲线一个对象”，只有内存里还是平行表。
2. **撤销事务靠手写三连。** `begin_edit` → 改 → `history.changed()` → `finish_edit` 共 54 处，漏写一步就会出现“改了但不能撤销”或“多出一步撤销”。
3. **分析操作重复。** 拟合、插值、非线性拟合、平滑、基线都重复同一套流程：
   1. 插入结果列（X、Y 各一次）；
   2. 找目标图形；
   3. 把结果挂到图层。
4. **界面测试辅助代码复制了 19 份**（`frame` 闭包或函数），另有点击宏、按文字找控件坐标的闭包各一份。
5. **两套 SVG 渲染栈并存。**
   - PNG 用 `resvg 0.37`（`usvg 0.37` / `rustybuzz 0.12`），PDF 用 `svg2pdf 0.13`（`usvg 0.45` / `rustybuzz 0.20`），exe 变大。
   - `deny.toml` 还有两条因此保留的“无人维护”豁免。
6. **现有脚本的入口说明不完整。** 仓库已有 `tools/check.py`、`tools/package_release.py`、`tools/third_party.py` 和 `docs/parity/build_parity.py`；1.7 重点补齐文档同步入口和 `CONTRIBUTING.md`，复用已有脚本。
7. **注释语言开始混杂。** 最近新增了约 49 行英文注释，其余是中文。

### 阶段 2：曲线数据模型统一（收益最大，中等风险）

把内存里的平行表换成“每条曲线一个对象”，与文件格式保持一致。

目标结构：

```rust
pub struct Layer {
    // …其余字段不变
    plots: Vec<Plot>,          // 取代 y_keys / x_by_y / base_by_y / row_by_y / line_only / curves
}
pub struct Plot {
    pub mapping: CurveMapping, // y、x、base、rows、line_only（已存在）
    pub style: CurveStyle,     // 已存在
}
```

曲线的身份就是 `DataRef { book, col }`，不再用 `"B@2"` 字符串。

步骤：

1. **2.1 加访问函数（已完成）。** 在 `Layer` 上提供 `plots(books)`、`plot(&DataRef, books)`、`plot_mut(&DataRef, books, edit)`、`add_plot(plot, books)`、`remove_plot(&DataRef)`、`retain_plots(books, keep)`。内部暂时仍读写旧字段。
2. **2.2 迁移调用点。** 把 62 处直接访问逐个改成走访问函数，按模块分批提交：分析操作（已迁移）、模型（已迁移）、界面属性窗口与图层内容（已迁移）、作图面板与导出（已迁移）、撤销内存估算（已收口）。
3. **2.3 换存储（已完成）。** 把 `Layer` 的存储换成 `Vec<Plot>`，删除旧字段。
   - 属性窗口原来用的字符串键改为 `DataRef`。
   - 文件格式不变（沿用当前版本的 `plots`），只删掉读写时“平行表 ↔ plots”的转换代码。
4. **2.4 集中清理（已完成）。** 删列、删表、删曲线统一经 `LayerSpec::retain_plots` 过滤和修复原始曲线对象。公开 `Layer::retain_plots` 保持仅筛选可解析在用曲线的既有语义；隐藏项和未绑定项的保留规则由各删除入口明确指定。

2.1 过渡接口约定：`books` 沿用 `BookLookup` 解析其他表的默认 X；读接口返回现有 `Plot` 描述快照，`plot_mut` 在闭包内修改后统一校验、写回并返回是否实际改变。曲线来源和旧键不能在闭包中换名，换来源使用移除后添加。添加不改绑主表，不改变图层默认 X、行范围或标签列。

接口只写入旧存储能表达的映射：已有默认 X 时，单条曲线显式改用行号会返回错误并保留原图层；默认 X 本来为空时继续支持行号。未绑定主表的旧裸键保留，不猜测数据来源。继承和显式覆盖在未修改时保持原样；2.3 已替换存储，并继续沿用这些公开操作规则。

验收：

- `page.rs` 和 `plotspec.rs` 之外，没有任何代码访问 `y_keys`、`x_by_y`、`base_by_y`、`row_by_y`、`line_only`、`curves`。
