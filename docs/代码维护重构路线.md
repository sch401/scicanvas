## 目标与原则

目标：让后续加功能时**改动集中在一处、出错能被测试抓住、新人（或 AI）能快速找到代码**。

每一步都必须遵守：

1. **只重构，不改行为。** 不顺带加功能、不改界面文字和布局、不改项目文件格式。
2. **每步一个提交**，提交前 `python tools/check.py` 全部通过。
3. **19 份 golden SVG、PDF/PNG 导出测试、项目文件往返测试结果不变。** 如果某步必须更新 golden，说明原因并单独提交。
4. 先加访问函数、再迁移调用点、最后删旧代码；不要一次性大替换。
5. 注释统一用中文；提交信息用英文。

### 结构性问题

1. **曲线数据用字符串键加多张平行映射表保存。** `Layer` 里的 `y_keys`、`x_by_y`、`base_by_y`、`row_by_y`、`line_only`、`curves` 都用 `"B"` 或 `"B@2"` 字符串关联同一条曲线。
   - 页面和映射模块之外有 62 处直接读写这些字段。
   - 删除一条曲线要同时清理 6 张表。最近修过的“删列后样式残留”“清空图层后标签列残留”都是漏清其中一张造成的。
   - 文件格式（v11 起的 `plots`）其实已经是“每条曲线一个对象”，只有内存里还是平行表。
2. **撤销事务靠手写三连。** `begin_edit` → 改 → `history.changed()` → `finish_edit` 共 54 处，漏写一步就会出现“改了但不能撤销”或“多出一步撤销”。
3. **分析操作重复。** 拟合、插值、非线性拟合、平滑、基线都重复同一套流程：
   1. 插入结果列（X、Y 各一次）；
   2. 找目标图形；
   3. 把结果挂到图层。
4. **界面测试辅助代码复制了 19 份**（`frame` 闭包或函数），另有点击宏、按文字找控件坐标的闭包各一份。
5. **两套 SVG 渲染栈并存。**
   - PNG 用 `resvg 0.37`（`usvg 0.37` / `rustybuzz 0.12`），PDF 用 `svg2pdf 0.13`（`usvg 0.45` / `rustybuzz 0.20`），exe 变大。
   - `deny.toml` 还有两条因此保留的“无人维护”豁免。
6. **现有脚本的入口说明不完整。** 仓库已有 `tools/check.py`、`tools/package_release.py`、`tools/third_party.py` 和 `docs/parity/build_parity.py`；1.7 重点补齐文档同步入口和 `CONTRIBUTING.md`，复用已有脚本。
7. **注释语言开始混杂。** 最近新增了约 49 行英文注释，其余是中文。

### 阶段 2：曲线数据模型统一（收益最大，中等风险）

把内存里的平行表换成“每条曲线一个对象”，与文件格式保持一致。

目标结构：

```rust
pub struct Layer {
    // …其余字段不变
    plots: Vec<Plot>,          // 取代 y_keys / x_by_y / base_by_y / row_by_y / line_only / curves
}
pub struct Plot {
    pub mapping: CurveMapping, // y、x、base、rows、line_only（已存在）
    pub style: CurveStyle,     // 已存在
}
```

曲线的身份就是 `DataRef { book, col }`，不再用 `"B@2"` 字符串。

步骤：

1. **2.1 加访问函数。** 在 `Layer` 上提供 `plots()`、`plot(&DataRef)`、`plot_mut(&DataRef)`、`add_plot()`、`remove_plot()`、`retain_plots()`。内部暂时仍读写旧字段。
2. **2.2 迁移调用点。** 把 62 处直接访问逐个改成走访问函数，按模块分批提交：分析操作、模型、界面属性窗口、图层内容、导出。
3. **2.3 换存储。** 把 `Layer` 的存储换成 `Vec<Plot>`，删除旧字段。
   - 属性窗口原来用的字符串键改为 `DataRef`。
   - 文件格式不变（仍是 v13 的 `plots`），只删掉读写时“平行表 ↔ plots”的转换代码。
4. **2.4 集中清理。** 删列、删表、删曲线只调用 `retain_plots`，一处清理就完整。

验收：

- `page.rs` 和 `plotspec.rs` 之外，没有任何代码访问 `y_keys`、`x_by_y`、`base_by_y`、`row_by_y`、`line_only`、`curves`。
- 现有的跨工作簿测试（`multi_book_layers.rs`）和项目往返测试全部通过，测试本身不改断言。
- 用 v0、v1、v10、v11、v13 各一个项目文件做“读入 → 保存 → 再读入”，结果相等。

### 阶段 3：编辑事务统一（中等风险）

1. **3.1 加统一入口。** 在 `SciApp` 上加：

   ```rust
   fn edit<T>(&mut self, label: &str, f: impl FnOnce(&mut Project) -> Result<Option<T>, String>) -> Option<T>
   ```

   它负责开始事务、调用 `f`，有改动才记一步，出错时回滚并写状态栏，最后统一做公式重算。
2. **3.2 替换调用点。** 把 54 处 `begin_edit`/`changed`/`finish_edit` 三连逐步换成 `edit`。实时预览这类需要合并成一步的连续编辑，保留现有的 `history_group` 机制，也封装成 `edit_grouped`。
3. **3.3 对话框改为两步。** 对话框结果统一成“生成 `Action` → `apply(action)`”。`app.rs` 的 `dialogs` 分派函数控制在 100 行以内。

验收：

- `app` 目录里 `begin_edit(` 只在 `edit` 和 `edit_grouped` 的实现中出现。
- 每个改项目的命令都有“一步撤销、一步重做”测试；可以在 1.2 的 `Harness` 里加一个通用断言。

### 阶段 4：分析操作拆分与去重（中等风险）

1. **4.1 按领域拆分。** `ops.rs` 拆成 `ops/` 目录：

   | 文件 | 内容 |
   | --- | --- |
   | `resolve.rs` | 分析来源解析 |
   | `fit.rs` | 线性、多项式、非线性拟合，置信带 |
   | `smooth.rs` | 平滑、归一化 |
   | `calculus.rs` | 微分、积分、SG 求导 |
   | `baseline.rs` | 基线 |
   | `fft.rs` | FFT 滤波、IFFT |
   | `recalc.rs` | 重算方式、操作记录、公式列 |
   | `columns.rs` | 插入结果列 |

2. **4.2 抽出公共流程。** 抽出 `fn write_result(&mut self, item, columns: Vec<Column>, link: ResultLink) -> ResultKeys`，统一“插入结果列 + 找图形 + 挂到图层”，替换各操作里的重复代码。
3. **4.3 拆分 `nlfit.rs`。** 把 `nlfit::guess`（244 行）按函数类别拆开：峰型、指数、S 型、幂函数。

验收：

- 拟合、平滑等数值测试（与 SciPy/NumPy 的对照）全部不改、全部通过。
- 单个文件少于 800 行（不含测试）。

### 阶段 5：依赖与渲染栈（需要验证输出，单独做）

1. **5.1 统一渲染栈。** 把 PNG 导出从 `resvg 0.37` 升到与 `svg2pdf 0.13` 同代的 `resvg 0.45`，全仓只留一套 `usvg` / `rustybuzz`。
2. **5.2 清理豁免。** 去掉 `deny.toml` 里因旧版本保留的豁免；`unused-ignored-advisory = "deny"` 会提示哪些已经不需要。
3. **5.3 对比导出效果。** 对每种图型对比升级前后的 PNG 像素差异，超过阈值的逐一确认。

验收：

- `cargo tree -d` 里不再出现两份 `usvg`、`rustybuzz`、`ttf-parser`。
- exe 体积比升级前小。
- PNG 像素差异在阈值内，或已逐一说明原因。

### 阶段 6：长期规范（持续执行）

1. **6.1 设上限。** 非测试代码单文件不超过 1500 行，单函数不超过 150 行。
   - 在 `clippy.toml` 设 `too-many-lines-threshold = 150`。
   - 先在已拆完的模块加 `#![warn(clippy::too_many_lines)]`，逐步扩大到全仓。
2. **6.2 写 `docs/ARCHITECTURE.md`（不超过两页）。**
   - 模块地图：核心库各模块职责，界面各模块职责。
   - 数据流：导入 → 工作簿 → 作图描述 → 场景 → 屏幕、SVG、PNG、PDF。
   - 撤销模型。
   - 文件格式版本规则：改格式时升版本号，并补迁移测试。
3. **6.3 统一注释语言。** 把近期新增的英文注释改成中文。
4. **6.4 每个新功能同时带三样东西：**
   - 核心测试；
   - 一步撤销的界面测试；
   - 涉及作图时，加 golden SVG 或导出测试。

## 建议顺序

```text
阶段 1（1.1 → 1.2 → 1.3 → 1.4 … 1.7）
  → 阶段 2（2.1 → 2.2 分批 → 2.3 → 2.4）
  → 阶段 3
  → 阶段 4
  → 阶段 5（可与阶段 3、4 并行，但单独提交）
  → 阶段 6 持续执行
```

阶段 1 完成后，后续每一步的改动范围都会小很多。阶段 2 解决的是近期 bug 最集中的地方，优先级最高。阶段 1 和 2 期间暂停新功能开发，避免和拆分互相冲突。
